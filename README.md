# Reimagining the Personal Music Experience

Integrated Design Thinking project: a Chrome Manifest V3 extension plus a responsive
companion web dashboard with a Python (Flask) backend and SQLite database.

## Regenerate the submission documents

```bash
python3 docs/build_presentation.py
python3 docs/build_paper.py
```

After new survey responses arrive, run the analysis script first, then these two
builders so every number in the PPT and paper matches the latest data.

### Presentation design rules (keep these when extending the deck)

`docs/build_presentation.py` enforces exactly **two font sizes** — 36pt hero,
20pt for everything else — through its `fs()` helper. Bold is applied only to
hero text, so a slide never reads as a jumble of competing weights and sizes.
`fit_height()` grows each text box using the same wide DejaVuSans measurement
as the checker, so text never overflows. To add a slide: write a `sN(prs)`
builder that calls `decorate()`, append it to `SLIDE_BUILDERS`, and add a note
to `docs/slide_notes.json`.

**The deck is light and lightly cartoony.** Every slide has a **pure white
background** and a bold colour stripe. The soft corner circles were removed —
on white they looked like a second pair of discs. A single, subtle vinyl
(disc, grooves, coloured label, spindle hole) appears only on the two sparse
bookend slides (1 and 15); content-heavy slides get none. **All text is
black**. Colours come from shapes, not typography.

**Four bright colours, used softly:** yellow `FFE22E`, aqua `5ED6C8`, blue
`45C4F8` and coral `FF7676` (coral only on the limitations slide). Aqua is the
bridge between yellow and blue, and `THEME` steps through them gradually so
consecutive slides never jump harshly. Green and purple are gone.

Boxes **pop out** with a full bright fill and **one 3pt black border**. There
is no inset wash, no box-edge bar and no per-box repeated rings — those read
as clutter. After rebuilding, run `python3 docs/check_layout.py` — it must
report **0 estimated overflowing text boxes**, and text must also stay inside
its coloured panel. Chart gridlines come from `webapp/analysis/analysis.py` —
regenerate charts before rebuilding the deck.

Four palette trial decks live in `docs/trials/` (see its README). Build any of
them with `python3 docs/build_presentation.py --palette <name> --out <file>`;
the plain command still rebuilds `docs/Presentation.pptx` with the default
palette.

## Run the dashboard

```bash
cd webapp
python3 -m pip install -r requirements.txt
python3 app.py
# open http://127.0.0.1:5000
```

Pages: `/` (My Music), `/discover`, `/vibe`, `/preferences`, `/study` (timed tasks + SUS),
`/results` (charts + anonymised data), `/health`, `/api/summary`.

## Regenerate all statistics after new survey responses

Export the updated Google Forms CSV into this folder, then:

```bash
python3 webapp/analysis/analysis.py \
  --csv "Music Streaming Platform Experience (Responses) - Form responses 1.csv"
```

This rewrites `data/survey_responses_anonymised.csv`, all five charts in `data/charts/`,
and `docs/statistical_results.md`. Every number in the presentation and viva documents is
taken from that report — update them if the figures change.

## Load the Chrome extension

`chrome://extensions` → Developer mode → Load unpacked → select `PersonalMusicExperience/`.

## Integrity note

All reported findings come from the real survey export. Two low-quality responses are
flagged in the report and none were silently removed. No survey responses were fabricated.
The single-contributor scope adaptation is disclosed in `docs/design_thinking_artefacts.md`.
