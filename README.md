# Reimagining the Personal Music Experience

Integrated Design Thinking project: a Chrome Manifest V3 extension plus a responsive
companion web dashboard with a Python (Flask) backend and SQLite database.

## Regenerate the submission documents

```bash
python3 docs/build_presentation.py
python3 docs/build_paper.py
```

After new survey responses arrive, run the analysis script first, then these two
builders so every number in the PPT and paper matches the latest data.

### Presentation design rules (keep these when extending the deck)

`docs/build_presentation.py` enforces exactly **two font sizes** — 36pt hero,
20pt for everything else — through its `fs()` helper. Bold is applied only to
hero text. `fit_height()` grows each text box using the same wide DejaVuSans
measurement as the checker, so text never overflows. To add a slide: write a
`sN(prs)` builder that calls `new()`, append it to `SLIDE_BUILDERS`, and add a
note to `docs/slide_notes.json`.

**Official theme — "Dandadan tinted".** Pale lime background `#F2F7EA`, two
dark-green text inks (`#1B5E3F` on the background, `#0E3B2A` in boxes), and
soft cream-yellow / green / teal boxes. Dark red is reserved for limitations.
A subtle vinyl (disc, grooves, coloured label, spindle hole) appears on eight
curated slides, placed at slide level behind content. **Only the bottom-right
slide number is shown** — the old top-left duplicate was removed.

**Charts:** all five real survey figures are generated by
`webapp/analysis/analysis.py` with light backgrounds, grids and large labels,
and each gets a **full-width evidence slide** (7–11). Never shrink a chart into
a corner. Boxes use **one 3pt dark border**. After rebuilding, run
`python3 docs/check_layout.py` — it must report **0 estimated overflowing text
boxes**, and text must also stay inside its coloured panel.

No palette trials remain; a plain `python3 docs/build_presentation.py` rebuilds
the single official `docs/Presentation.pptx`.

## Run the dashboard

```bash
cd webapp
python3 -m pip install -r requirements.txt
python3 app.py
# open http://127.0.0.1:5000
```

Pages: `/` (My Music), `/discover`, `/vibe`, `/preferences`, `/study` (timed tasks + SUS),
`/results` (charts + anonymised data), `/health`, `/api/summary`.

## Regenerate all statistics after new survey responses

Export the updated Google Forms CSV into this folder, then:

```bash
python3 webapp/analysis/analysis.py \
  --csv "Music Streaming Platform Experience (Responses) - Form responses 1.csv"
```

This rewrites `data/survey_responses_anonymised.csv`, all five charts in `data/charts/`,
and `docs/statistical_results.md`. Every number in the presentation and viva documents is
taken from that report — update them if the figures change.

## Load the Chrome extension

`chrome://extensions` → Developer mode → Load unpacked → select `PersonalMusicExperience/`.

## Integrity note

All reported findings come from the real survey export. Two low-quality responses are
flagged in the report and none were silently removed. No survey responses were fabricated.
The single-contributor scope adaptation is disclosed in `docs/design_thinking_artefacts.md`.
